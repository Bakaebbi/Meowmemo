# Meowmemo

**Каждый день немного заботы.**

Meowmemo – уютный дневник ежедневного ухода за одним котиком. Помогает отмечать задачи, записывать короткие наблюдения и смотреть историю за последние семь календарных дней.

Учебный frontend-проект на HTML, CSS и Vanilla JavaScript с ES Modules. Для разработки и сборки используется Vite.

## Возможности

- Выбор имени котика при первом запуске и возможность изменить его в профиле.
- Загрузка аватара и кадрирование: перемещение фото и изменение масштаба.
- Пять начальных задач по уходу. Можно добавлять свои, переименовывать и удалять существующие.
- Отметки выполнения и прогресс за день.
- Ежедневная заметка до 500 символов.
- История за сегодня и шесть предыдущих дней.
- Автоматическое сохранение в localStorage и восстановление после перезагрузки.
- Переключение на новый день без перезагрузки страницы.
- Адаптивное оформление от 320 px и управление с клавиатуры.

Список задач общий для всех дней. Их выполнение и заметки хранятся отдельно для каждой локальной календарной даты. Добавлять задачи заново каждый день не нужно. Постоянный `id` позволяет переименовывать задачу без потери её отметки.

## Запуск

При первом открытии приложение предложит ввести имя котика. Имя по умолчанию не подставляется. После сохранения приветствие больше не появляется; изменить имя можно в профиле. Существующие сохранённые имена продолжают использоваться.

Для запуска нужны Node.js и npm. Проект проверен с Node.js 26.13.0 и npm 12.2.1.

Открой терминал в папке проекта и установи зависимости:

```bash
npm ci
```

Запусти сервер разработки:

```bash
npm run dev
```

Открой **http://127.0.0.1:5173/**. Vite обновляет страницу при изменении файлов. Чтобы остановить сервер, нажми `Ctrl + C` в терминале.

Используй этот способ запуска вместо открытия `index.html` через `file://`. Для загрузки JavaScript-модулей нужен локальный HTTP-сервер.

Порт разработки закреплён в конфигурации. Если он занят, Vite сообщит об ошибке вместо запуска на другом порту.

## Проверки и сборка

```bash
npm test
```

Запускает автоматические тесты через встроенный тестовый инструмент Node.js. Они проверяют календарные даты, структуру задач, сохранение и загрузку, историю, ошибки хранилища и границы кадрирования. Новые тестовые пакеты не требуются.

```bash
npm run build
```

Создаёт готовую версию сайта в папке `dist/`.

```bash
npm run preview
```

Открывает локальный сервер собранной версии: **http://127.0.0.1:4173/**. Перед предпросмотром нужно выполнить сборку. Это проверка результата сборки, а не сервер для публикации в интернете.

Для публикации нужен результат из `dist/`. Ресурсы собираются с относительными путями (`base: './'`), подходящими для размещения в подпапке GitHub Pages.

В репозитории подготовлен ручной workflow `.github/workflows/pages.yml`:

1. На GitHub открой `Settings → Pages` и выбери источник `GitHub Actions`.
2. Открой `Actions → Deploy Meowmemo to Pages`.
3. Нажми `Run workflow`, выбери ветку `master` и подтверди запуск.
4. Дождись завершения проверок, сборки и публикации. Ссылка появится в результате workflow и в `Settings → Pages`.

Публикация запускается вручную. После следующих изменений и push нужно снова запускать этот workflow.

`node_modules/` и `dist/` исключены из Git. `package-lock.json` хранится в репозитории, чтобы `npm ci` устанавливал зафиксированные версии зависимостей.

## Аватар

Нажми на аватар в профиле и выбери JPG, PNG или WebP размером до 10 МБ. В окне кадрирования перетаскивай фотографию и меняй масштаб ползунком. Стрелки клавиатуры перемещают фото, `Escape` отменяет выбор.

Новый аватар сохраняется только после нажатия «Сохранить фото». Он уменьшается до 256×256 пикселей и хранится как JPEG. Исходная фотография не отправляется на сервер и не сохраняется в приложении. Для нового кадрирования нужно снова выбрать исходный файл.

## Хранение данных

Все данные остаются в localStorage текущего браузера. Авторизации, сервера и облачной синхронизации нет.

- Данные не переносятся автоматически на другое устройство, в другой браузер или профиль.
- Хранилище привязано к протоколу, имени хоста и порту. `localhost:5173`, `127.0.0.1:5173` и `127.0.0.1:4173` используют разные хранилища.
- После публикации сайт тоже получит отдельное хранилище. Записи по прежнему адресу останутся там.
- Очистка данных сайта в браузере удалит сохранённые записи. В приватном режиме они обычно удаляются после закрытия приватных окон.
- Место в localStorage ограничено. При ошибке записи приложение сообщает, что сохранение не удалось.
- История показывает семь дней. Более старые записи автоматически не удаляются.

Экспорт и импорт данных пока не реализованы.

## Ручная проверка

Основной браузер разработки – Brave. После изменений стоит проверить:

1. Отметки задач, добавление, переименование и удаление, включая удаление последней задачи.
2. Восстановление имени, аватара, задач и заметки после перезагрузки по тому же адресу.
3. Кадрирование мышью и касанием, сохранение и отмену выбора фото.
4. Обновление истории после изменения данных.
5. Формы с клавиатуры: `Tab`, `Пробел`, `Enter` и `Escape`.
6. Длинные названия и заметки, ширину от 320 px и отсутствие горизонтальной прокрутки.
